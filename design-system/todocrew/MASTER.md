# Cofoco design system

Status: **Owner-approved V1 UI baseline; production UI pending**
Updated: 2026-09-28

Cofoco is a macOS desktop companion, not a branded dashboard. Its visual identity comes from the pet, the speech-bubble silhouette, and the small project marks. The application UI follows the current macOS appearance with no product key color.

## Character

- **Native desk companion:** a borderless macOS accessory window anchored above the pet.
- **System glass, quiet content:** translucent material establishes the outer layer; rows remain calm and legible.
- **Compact by default:** the primary Todo list is the bubble itself, not a preview of a larger window.
- **Cute through shape and behavior:** the pet and bubble carry personality; controls use familiar macOS language.
- **Stateful low motion:** neutral blink, breath, alert-present arm circle with a subtle head bob, and in-progress dance are tied to a clear state, with a complete reduced-motion path.

Avoid a brand accent, tinted page backgrounds, AI gradients, card grids, oversized controls, gamification, streaks, pet-care meters, live agent indicators, and decorative motion unrelated to state. Restrained idle/resting loops, the alert-present arm circle, the in-progress dance, and the sequenced dots are allowed only while their corresponding state is visible.

The wireframe's Usagi images are user-supplied reference assets for motion/scale review, not approved shipped artwork. Its current experiment uses ten smooth outlined transparent frames on normalized 768×512 canvases: stand/neutral blink, a three-image `1-2-3-2-1` alert arm circle whose very short arms overlap in front while the head subtly moves forward/back, a three-image `A-B-A-C-A` yellow-suit lower-body sway with an upright face and ears and the same left hand pointing, and lie/exhale-inhale. The renderer swaps complete frames and never creates a pose by translating or rotating another frame. The character direction is round, minimally articulated, and carefree rather than fierce or heroic. Custom packs may still provide only one `idle` frame; each slot accepts ordered frames and missing optional slots fall back to idle. Prefer transparent PNG/WebP with consistent canvas, baseline, outline weight, face-to-body ratio, and visual scale. Imported files remain local and must not be recolored, stylized, or regenerated by Cofoco.

## Appearance and material tokens

Light and dark follow the system. Values below describe the HTML wireframe; production should use semantic macOS colors and materials instead of hard-coded equivalents.

| Token | Light approximation | Dark approximation | Use |
|---|---:|---:|---|
| `--desktop` | system wallpaper | system wallpaper | Context behind the accessory window |
| `--glass` | `rgba(248,248,250,.72)` | `rgba(30,30,32,.72)` | Main bubble material |
| `--glass-strong` | `rgba(255,255,255,.86)` | `rgba(38,38,40,.86)` | Change bubble and menus |
| `--content` | `rgba(255,255,255,.44)` | `rgba(255,255,255,.055)` | Hover/selected content layer |
| `--ink` | `#1D1D1F` | `#F5F5F7` | Primary label |
| `--ink-secondary` | `rgba(60,60,67,.68)` | `rgba(235,235,245,.60)` | Metadata and secondary label |
| `--separator` | `rgba(60,60,67,.20)` | `rgba(84,84,88,.56)` | Dividers and subtle outlines |
| `--system-accent` | user preference | user preference | Keyboard focus and native primary controls only |
| `--success` | system green | system green | Completed state, always with checkmark |
| `--danger` | system red | system red | Destructive text, always with icon/text |

There is no Cofoco key color. Project marks are the only persistent chroma in the list and identify a scope, not a brand or status.

Use standard material for the bubble's content layer and reserve stronger Liquid Glass treatment for transient functional elements such as the change bubble and interactive controls. Respect Reduce Transparency and Increase Contrast by falling back to an opaque system background and stronger separators.

## Project marks

- Place the mark between status control and Todo title.
- Use exactly one visible character derived from the current display name. It is colored text, not a filled chip, pill, or icon tile.
- Derive the hue from the stable Project ID, not the name, so a rename does not change recognition.
- Choose from a curated semantic palette and calculate a legible foreground for light/dark appearances. Do not generate unrestricted RGB values.
- Personal uses a neutral `P`, not a colored project identity.
- Hover and keyboard focus show only the full Project name. The accessibility label exposes the same name; bound directories stay in Project settings.
- Duplicate initials are allowed because color and the full tooltip disambiguate them; settings may later support an owner-selected character.

## Type

- UI/body: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", sans-serif`.
- Wordmark and brief pet speech: `ui-rounded, "SF Pro Rounded", -apple-system, sans-serif`.
- Scale: 11 metadata, 12 secondary labels, 13 list rows/body, 15 screen title, 17 detail title.
- Use 400 body, 500 controls, and 600 headings. Todo rows are one line; the full title appears in detail and accessibility text.

## Geometry and density

- 4px base spacing; common steps 4 / 6 / 8 / 12 / 16.
- Main Todo bubble: 324px wide, normally 280–390px tall; scrolls when content exceeds the available height.
- Change bubble: 300–324px wide and independently sized, stacked above the main bubble one at a time.
- Todo detail replaces the main bubble content and may grow to 356px wide for notes.
- List row: 36px visual height with at least a 28px pointer target. Keyboard focus remains clearly visible.
- Header: 38px. The resting add action is a 32px floating circle; its expanded composer overlays the list bottom without resizing rows.
- Radius: 20px main bubble, 16px change bubble, and 9px controls. Project marks have no container or radius.
- Use one restrained floating-window shadow. The main list has no internal separators; rows use whitespace and a transient hover/focus fill, never nested cards or shadows.

The 36px row is a desktop-density choice for precise pointer input, not a mobile touch target. Important actions must also be reachable by keyboard and through the Todo detail screen.

## Icons and controls

- Prefer SF Symbols in production. The wireframe uses text/SVG stand-ins only.
- Use 13–15px visual icons in 28–32px pointer targets.
- Row order is fixed: checkbox → project mark → title → start/more.
- Use the SF Symbol `play.fill` for start and horizontal `…` for in-progress. Hover/focus reveals the open-row start action; it stays keyboard reachable.
- Animate the three in-progress dots with transform only: a short sequential rise/settle followed by a long rest. Use static `…` under Reduce Motion. This is a Todo-status cue, never agent-presence evidence.
- Clicking the title opens detail. Clicking the checkbox or right action changes status and never opens detail.
- Buttons preserve bounds across hover/press. Feedback uses material/fill/opacity, not layout-moving scale.

## Window and component policy

- **Pet only:** clicking the pet restores the Todo bubble; a menu-bar item can restore, move, open settings, or quit.
- **Main Todo bubble:** the complete list experience, with remembered All/Personal/Project scope. Its header is one `Todo ▾` filter; choosing a scope replaces `Todo` with the scope name. At rest only a circular `+` is visible; it reveals a borderless natural-language composer with a Project selector above it and Personal selected by default. There is no expanded list view.
- **Todo detail:** replaces the main bubble content, with Back, the full Project name above title/status, Steps, Notes, and history. Do not repeat the one-character project mark here.
- **Change bubble:** appears immediately above the main bubble for Todo-level changes or proposals. Show one event at a time and a queue position such as `1 of 3`; proposals include Reject/Accept.
- **Settings/Trash:** secondary screens reached from the bubble menu. They are not tabs competing with the daily list. Pet settings import local pose files and provide a copyable external-generation prompt; there is no in-app generation API in V1.
- Agent provenance lives in detail/history and proposal context, not in every Todo row.
- Step/Note changes remain quiet in detail/history and do not create a change bubble.

## Motion

- Fast feedback 80ms, content transition 140ms, bubble enter/exit 180/120ms.
- Animate opacity and transform only. A new change bubble rises a few points above the existing stack; the pet uses its noticed pose while any alert remains visible.
- Resolve pet pose in strict order: closed Todo bubble → `resting`; open with visible alert → `noticed`; otherwise visible in-progress Todo → `working`; otherwise `idle`.
- Pet motion uses one preloaded image element and swaps its source, never stacked images or an opacity crossfade. Idle and resting use a six-second loop: frame 2 from 450–1150ms and frame 1 for the remaining 4.85 seconds. Noticed (alert arm circle) plays three images as `1-2-3-2-1` at 320ms between every frame and next-loop boundary, repeats its 1.28-second loop four times, then rests on frame 1 for four seconds. Working (in-progress dance) keeps `A-B-A-C-A` at 160ms per frame and loop boundary, repeats its 0.64-second loop four times, then rests on A for four seconds. Treat these as review values, not fixed production constants.
- Resolving one change transitions to the next queued change without moving the Todo bubble.
- `prefers-reduced-motion: reduce` disables displacement, pet reactions, and dot movement; state remains immediately legible through static `…`.

## Prototype and implementation boundary

[Interactive wireframe](../../docs/wireframes/todocrew-v1.html) is a dependency-free design artifact. It approximates macOS blur in HTML; it does not select a desktop framework, persist data, contact MCP, or count as Cofoco feature implementation.

The production runtime must prove native macOS window behavior, semantic materials, light/dark appearance, Reduce Transparency, Increase Contrast, VoiceOver, keyboard order, multiple displays, focus behavior, and transparent-window hit testing. A framework that can only imitate these behaviors is not sufficient without a successful spike.

The owner approved the UI baseline on 2026-09-28. The separate [native runtime experiment and decision](../../docs/decisions/0004-macos-runtime.md) selected SwiftUI/AppKit and verified its initial window/service/package feasibility. That result does not complete the production accessibility, appearance or multi-display checks above.
